# Quest Manager 웹 관리 시스템 기획 문서

## 1. 프로젝트 개요

이 프로젝트는 Unity 게임에서 사용하던 퀘스트 시스템을 웹 서비스로 관리해보고, AI를 활용해 편리하게 생성해보는 프로젝트이다.
기존 게임 시스템에서는 NPC가 플레이어에게 도움을 요청하고, 플레이어가 퀘스트를 수락한 뒤 조건을 만족하면 보상을 받는 구조를 가진다. 
이 프로젝트에서는 해당 구조를 웹 서비스의 도메인 모델로 정리하고, 추후 백엔드 API, 프론트엔드 UI, 데이터베이스 설계, AI 기능 확장까지 이어질 수 있도록 한다.

## 2. 프로젝트 목적

이 프로젝트의 목적은 단순한 게임 기능 구현을 넘어서, 하나의 도메인을 분석하고 웹 서비스 구조로 설계하는 과정을 진행해보기 위함이다.
주요 목적은 다음과 같다.

Unity 기반 퀘스트 시스템을 웹 서비스 도메인으로 변환한다.
NPC, Quest, Reward, Progress 등의 개념을 데이터 모델로 정리한다.
백엔드 API와 프론트엔드 화면으로 확장 가능한 구조를 만든다.
추후 AI 기능을 추가하여 퀘스트 추천, 자동 설명 생성, 진행 상태 분석 등의 기능으로 확장할 수 있게 한다.

## 3. 핵심 도메인

Quest Manager의 핵심 도메인은 “사용자가 퀘스트를 받고, 진행하고, 완료하는 과정”이다.

이 도메인은 다음과 같은 흐름을 가진다.

NPC가 퀘스트를 제공한다.
사용자는 퀘스트 목록을 확인한다.
사용자는 원하는 퀘스트를 수락한다.
사용자는 퀘스트 목표를 진행한다.
조건을 만족하면 퀘스트를 완료한다.
완료된 퀘스트에 대한 보상을 받는다.
사용자는 완료 기록과 진행 상태를 확인할 수 있다.

## 4. 주요 사용자 시나리오

4.1 퀘스트 확인

사용자는 현재 받을 수 있는 퀘스트 목록을 확인할 수 있다.
각 퀘스트에는 제목, 설명, 제공 NPC, 목표, 보상, 난이도, 상태 정보가 포함된다.

4.2 퀘스트 수락

사용자는 특정 퀘스트를 선택하여 수락할 수 있다.
퀘스트를 수락하면 해당 퀘스트는 사용자의 진행 중 퀘스트 목록에 추가된다.

4.3 퀘스트 진행

사용자는 퀘스트 목표를 수행하면서 진행도를 갱신할 수 있다.
예를 들어 “아이템 3개 수집하기” 퀘스트라면 현재 수집한 아이템 개수를 기준으로 진행도가 표시된다.

4.4 퀘스트 완료

퀘스트의 완료 조건을 만족하면 사용자는 퀘스트를 완료할 수 있다.
완료된 퀘스트는 완료 목록으로 이동하고, 보상이 지급된다.

4.5 보상 획득

퀘스트 완료 후 사용자는 경험치, 골드, 아이템 등의 보상을 받을 수 있다.
웹 서비스 관점에서는 보상 정보를 사용자 계정 또는 프로필 데이터에 반영할 수 있다.

## 5. 주요 도메인 개념

5.1 User

서비스를 사용하는 플레이어 또는 계정을 의미한다.
User는 여러 개의 퀘스트를 수락하고 진행할 수 있으며, 완료한 퀘스트 기록과 보상 정보를 가진다.

5.2 NPC

퀘스트를 제공하는 캐릭터를 의미한다.
NPC는 여러 개의 퀘스트를 제공할 수 있으며, 이름, 설명, 역할, 이미지 등의 정보를 가질 수 있다.

5.3 Quest

사용자가 수행해야 하는 임무를 의미한다.
Quest는 제목, 설명, 목표, 완료 조건, 보상, 난이도, 상태 등의 정보를 가진다.

5.4 Quest Progress

사용자가 특정 퀘스트를 얼마나 진행했는지를 나타내는 정보이다.
예를 들어 목표 수량, 현재 수량, 진행률, 상태 값 등을 포함할 수 있다.

5.5 Reward

퀘스트 완료 시 사용자에게 지급되는 보상이다.
보상은 골드, 경험치, 아이템, 칭호, 해금 요소 등으로 구성될 수 있다.

## 6. 퀘스트 상태 정의

퀘스트는 다음과 같은 상태를 가진다.

상태	설명
Available	사용자가 아직 수락하지 않았고 수락 가능한 상태
Accepted	사용자가 수락했지만 아직 완료하지 않은 상태
InProgress	사용자가 진행 중인 상태
Completable	완료 조건을 만족했지만 아직 완료 처리하지 않은 상태
Completed	완료 처리와 보상 지급이 끝난 상태
Failed	제한 시간 초과 또는 조건 실패로 완료할 수 없는 상태

## 7. MVP 범위

초기 버전에서는 복잡한 게임 시스템 전체를 구현하지 않고, 퀘스트 관리의 핵심 흐름만 구현한다.

MVP 범위는 다음과 같다.

퀘스트 목록 조회
퀘스트 상세 조회
퀘스트 수락
퀘스트 진행도 갱신
퀘스트 완료
보상 지급
완료한 퀘스트 기록 조회

## 8. MVP에서 제외할 기능

초기 버전에서는 다음 기능을 제외한다.

실시간 멀티플레이
복잡한 전투 시스템
인벤토리 전체 시스템
아이템 장착 시스템
NPC 호감도 시스템

이 기능들은 추후 확장 기능으로 고려한다.

## 9. 웹 서비스 관점의 해석

Quest Manager는 게임 시스템이지만, 웹 서비스 관점에서는 일종의 “작업 관리 시스템”으로 해석할 수 있다.
퀘스트는 사용자가 수행해야 할 작업이며, NPC는 작업을 요청하는 주체이고, 보상은 작업 완료에 따른 결과이다.
따라서 이 프로젝트는 게임 도메인을 기반으로 하지만, Todo 서비스, 업무 관리 시스템, 목표 달성 서비스와 유사한 구조로 확장할 수 있다.

## 10. AI 확장 가능성

추후 AI 기능을 추가한다면 다음과 같은 방향으로 확장할 수 있다.

사용자의 진행 상태를 분석하여 다음 퀘스트 추천
퀘스트 제목과 설명 자동 생성
NPC 대사 자동 생성
사용자의 플레이 기록을 바탕으로 난이도 조정
완료 기록을 요약하여 성장 리포트 생성
자연어 입력을 기반으로 퀘스트 생성

초기 버전에서는 AI 기능을 바로 구현하지 않고, 추후 확장 가능한 구조를 고려하여 문서와 데이터 모델을 설계한다.
